# Git 工作流技能 (Git Workflow Skill)

## 核心原则
- **精准提交**：每个 commit 应当聚焦于一个原子性的逻辑变更，避免混杂多个不相关的改动。
- **清晰信息**：commit message 必须准确反映改动的意图和范围，方便回溯审查。
- **安全第一**：提交前务必 review 所有改动，确保没有泄露敏感信息（密钥、密码等）。

## 提交流程 SOP

### Step 1：检查当前状态
使用 `git diff --stat` 或 `git status` 了解当前的变更概览和涉及的文件列表。

### Step 2：审查具体改动
使用 `git diff` 逐文件审查改动内容，确认每一处修改的合理性和准确性。

### Step 3：编写 Commit Message
遵循以下规范生成 commit message：

- **格式**：`<类型>(<作用域>): <简要描述>`
  - 类型：`feat`(新功能)、`fix`(修复)、`refactor`(重构)、`docs`(文档)、`chore`(杂项)
  - 作用域：受影响的模块或文件名
  - 描述：简短的改动摘要（中文或英文）

- **正文**（可选）：换行后详细说明改动的背景、动机和具体做法。

- **尾部引用**（可选）：如果有关联的 issue 或需求，在末尾标注。

### Step 4：执行提交
使用 `git add` 暂存改动后，通过 `git commit` 提交。

### Step 5：推送远端
确认提交无误后，执行 `git push` 推送到远端仓库。

## 禁止事项
- ❌ 严禁使用 `git commit -am "update"` 这种敷衍的提交。
- ❌ 严禁将未完成、编译不过或有语法错误的代码提交到仓库。
- ❌ 严禁在 commit message 中使用无意义的词汇如 "fix bug"、"change"、"修改" 等。
- ❌ 严禁直接推送未经 review 的第三方依赖变更。
